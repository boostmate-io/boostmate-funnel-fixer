- Offer Builder and public Offer Generator logic lives only in `supabase/functions/_shared/offerIntelligence/` (fixed Value Equation rubric scored in code, per-operation instructions + strict output schemas, writes mapped via `offerAiPolicy`). Why: one engine for authenticated and public experiences without duplicated prompts or a second offer model.
- Public Offer Generator results live only in `public_offer_generations` (RLS on, no browser access); `offer-generator-public` creates/unlocks them and `claim-offer-generation` turns a claimed result into a NEW additional Core Offer. Why: lead data stays server-controlled and claiming never overwrites existing workspace offers.
- Builder sessions live only in `offer_builder_sessions` (owner + workspace RLS, `version` optimistic locking); the `offer-builder` function uses the caller JWT and takes the category from the saved offer. Sessions never write offers until final approval.
